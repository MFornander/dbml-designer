- [x] Arrange by group (issue #2): Arrange in the header's View menu lays out the active view with an in-house layered layout (`src/engine/geometry/arrange.ts`, no new dependency). Undo arrange (View menu, the notice's Undo link, or ⌘Z / Ctrl+Z outside text fields and editors) restores the layer from before in one step while nothing else has changed it. - [x] Engine and editor split (issue #8). Two npm workspace packages. `packages/engine` (`@dbml-designer/engine`) draws a diagram from its own JSON model (`model.ts`, checked by `MODEL_SCHEMA` and `checkModel`), knows no DBML, editor, or file, and keeps everything per instance: `createEngine()` ties a model, its views, its layered layout with inheritance and arrange-with-undo, and display options together; `EngineDiagram` draws one; `snapshot()` and `restore()` move the layout as plain data; every element can carry an opaque `source` handed back with clicks and hovers. Now the column pair (`DepColumnVM`, key `dep:a(c)->b(c)`) holds every mapping between those columns in `mappings` (`DepMappingVM`, key `dep:a(c)->b(c)#kind`, or the pair's key for a dep without a kind), strongest kind first, each with its own name, note, and metadata. The pair is still drawn as one curve, styled by its strongest kind (`value`, then `row`), so a key column that is both projected and joined on does not draw twice; its tooltip lists every kind.

- [x] Element events and the viewport (engine 0.4.0): `element-click` and `element-hover` (`onElementClick`, `onElementHover` for `mount`) report every table, field, partial badge, ref, lineage edge or column pair, group, and note, as the existing `HoverTarget`, with its `source` and its rectangle in client coordinates; a click's `preventDefault()` keeps the engine from pinning and selecting. `engine.rectOf(key)` works the rectangle out from the layout, so it stays right through pan, zoom, and redraws. `engine.viewport`, `setViewport`, `fit(keys?)`, and `viewport-change` read and set the pan and zoom. Display option `revealAdded` (`pan`, `fit`, `none`) says what the view does when an update adds tables; `fit` keeps a growing walk fitted until the user pans or zooms. Pressing a table without moving it no longer ends the automatic fit.

- [x] Host highlight and dim (engine 0.4.1): `engine.highlight(keys, { dim, accent })` lights tables, fields, edges, groups, and notes by key on top of hover and pin, as an overlay that moves and stores nothing. A mapping key lights its column pair, drawn even while lineage is drawn by table pair; `dim` fades what the highlight does not keep (the keys, the tables of their fields and at their edges' ends, a column pair's table pair, their groups), and `accent` draws some keys more strongly. Dimmed elements still take hovers and clicks, and a hover lights them through the dim; host-lit edges get no walking ants.

- [x] Tooltip control (engine 0.4.2): `tooltipFilter(target)` on `EngineDiagram`, `DiagramCanvas`, and `mount` is asked before the engine shows its tooltip for a hovered element; returning false leaves the element to the host's own popover, so a host's roll-over and the engine's tooltip never show together.

- [x] Lineage by kind (engine 0.4.3): display option `lineageKinds` (null for all) draws only the deps of the kinds listed, and those without a kind; a column pair shows while one of its mappings does, styled by the strongest shown, a table pair while one of its deps does, and the legend lists only what is drawn. The filter applies to the model drawn, so hover, tooltips, highlight, placement, and Arrange follow it.

- [x] Chips in table headers (engine 0.5.0): `engine.setChips(map)` puts the host's chips after a table's name, outlined (a kind) or filled (a status, colored by severity), each `chipWidth` wide with its label cut to fit, so case switches never resize a table; a chip's note is its tooltip, and its clicks and hovers reach the host as a `chip` target with its own rectangle. Not part of the model, and not stored.
